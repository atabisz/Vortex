## Goal

RC tag pushed → release-linux.yml runs successfully → GitHub Release with AppImage + .deb published → artefacts downloaded + SHA256s captured.

## Steps

1. **Confirm starting state.**

    ```
    git rev-parse --abbrev-ref HEAD       # expect: v8.0/config-bucket
    git status --short                    # expect: empty
    LOCAL_HEAD=$(git rev-parse HEAD)
    REMOTE_HEAD=$(git ls-remote git@github.com:atabisz/Vortex.git refs/heads/sync/upstream-v2.0.0 | awk '{print $1}')
    test "$LOCAL_HEAD" = "$REMOTE_HEAD"   # local must match remote before tagging
    ```

    If local ≠ remote, push v8.0/config-bucket first (additive) before tagging — the tag must point at a commit visible on the remote.

2. **Confirm gh auth.** Per CLAUDE.md memory "GitHub auth token", `GH_TOKEN` is available for atabisz when gh auth is expired:

    ```
    gh auth status || (export GH_TOKEN="<from CLAUDE.md memory>" && gh auth status)
    ```

3. **Create annotated SSH-signed tag.**
    ```
    git tag -a v2.0.0-linux-rebased-rc1 \
      -m "RC tag for Phase 29 SYNC-33 part B — triggers release-linux.yml CI build.
    ```

Per D-29-04 — RC tag is a deliberate throwaway. Canonical milestone tag
v2.0.0-linux-rebased is created in Phase 30. This RC + its release will be
deleted in Phase 30 cleanup per D-29-04 (gh release delete v2.0.0-linux-rebased-rc1 --cleanup-tag)."
git tag --verify v2.0.0-linux-rebased-rc1 2>&1 | head # expect: SSH signature good

```
Note: SSH signing of tags requires `git config tag.gpgsign true; git config gpg.format ssh; git config user.signingkey ~/.ssh/id_ed25519.pub`. If commit signing was set up in 29-00, tag signing should work too — verify with `git tag --verify`.

4. **Push the tag.** Tags are additive — no `--force-with-lease` needed.
```

git push git@github.com:atabisz/Vortex.git v2.0.0-linux-rebased-rc1

```
Confirm:
```

git ls-remote --tags git@github.com:atabisz/Vortex.git | grep v2.0.0-linux-rebased-rc1

```

5. **Monitor `release-linux.yml`.** Tag push triggers the workflow per its `on: push: tags: ['v*']` filter.
```

gh run list -R atabisz/Vortex --workflow=release-linux.yml --limit 5

# find the run triggered by tag v2.0.0-linux-rebased-rc1 (most recent, status in_progress)

RUN_ID=<from gh output>
gh run watch $RUN_ID -R atabisz/Vortex

```
Expected wall-clock: ~12–15 min per CONTEXT notes. If the run fails (R2 in CONTEXT risk register), capture the failing step + log line, surface to user — repair-vs-defer call per CONTEXT.

6. **Verify GitHub Release published.**
```

gh release view v2.0.0-linux-rebased-rc1 -R atabisz/Vortex

```
Expect: AppImage asset + .deb asset attached.

7. **Download artefacts locally.**
```

mkdir -p ~/Downloads/vortex-rc1
gh release download v2.0.0-linux-rebased-rc1 -R atabisz/Vortex -D ~/Downloads/vortex-rc1
ls -la ~/Downloads/vortex-rc1/
sha256sum ~/Downloads/vortex-rc1/_.AppImage ~/Downloads/vortex-rc1/_.deb

