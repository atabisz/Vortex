## Goal

Capture `pnpm lint:ci` warning count on `master` and embed it in `29-LINT-BASELINE.md` so 29-05 can compute the SYNC-32 delta. Return cleanly to `v8.0/config-bucket`.

## Steps

1. **Confirm starting state.**

    ```
    git rev-parse --abbrev-ref HEAD       # expect: v8.0/config-bucket
    git rev-parse HEAD                    # expect: da282aaf4 (or descendant)
    git status --short                    # expect: empty
    git ls-remote git@github.com:atabisz/Vortex.git refs/heads/sync/upstream-v2.0.0
    ```

    If working tree is dirty, stop and surface to user. If HEAD is not da282aaf4 or a descendant on `v8.0/config-bucket`, stop.

2. **Configure SSH commit signing for this session** (CLAUDE.md memory "SSH commit signing" — never GPG).

    ```
    git config commit.gpgsign true
    git config gpg.format ssh
    git config user.signingkey ~/.ssh/id_ed25519.pub
    ```

3. **Stash + checkout master.** Even if the working tree is clean, do `git stash --include-untracked` defensively so any tooling-generated noise (e.g. node_modules drift) doesn't follow the checkout.

    ```
    git stash --include-untracked
    git checkout master
    ```

4. **Install + run lint:ci on master.** `master` may have a different lockfile state than v8.0/config-bucket; run `pnpm install` first to be safe.

    ```
    pnpm install
    pnpm lint:ci 2>&1 | tee /tmp/lint-master.log
    echo "exit=$?"
    ```

    Capture: exit code, total `warning` count, total `error` count, per-workspace breakdown if `lint:ci` emits one. Expected: exit 0 with some warnings (lint:ci tolerates warnings, errors only fail it).

5. **Return to v8.0/config-bucket.**

    ```
    git checkout v8.0/config-bucket
    git stash pop
    git status --short                    # expect: empty
    ```

    If `git stash pop` fails (no stash because step 3 was a no-op), that's fine — just confirm `git status --short` is empty.

6. **Write `29-LINT-BASELINE.md`** with two sections:
    - `## Master baseline` — workspace name → warning count → error count table; total counts; the full `/tmp/lint-master.log` quoted in a fenced code block so the evidence survives /tmp clearing.
    - `## v8.0/config-bucket result` — placeholder section: `_To be filled by Plan 29-05._`
    - Header: branch HEADs (master SHA, v8.0/config-bucket SHA), capture timestamp, `pnpm` + `node` versions for reproducibility.

7. **Commit.**

    ```
    git add -f .planning/phases/29-build-verification/29-LINT-BASELINE.md
    git commit -m 'docs(29-00): phase 29 setup — lint:ci master baseline captured'
    git log -1 --show-signature
    ```

    Verify the signature line shows `Good "git" signature` (SSH).

8. **Do NOT push.** Per CONTEXT.md and Phase 28 cadence, push happens via 29-10 done-gate (and per-plan pushes for individual evidence commits as we go — Phase 29 commits are docs-only, additive over Phase 28, no force-push needed). Actually — Phase 29 follows Phase 28's cadence: each plan's commit is pushed after it lands so 29-10 just confirms the final state. Push here:
