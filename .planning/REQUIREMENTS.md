# Requirements: Vortex Linux Port — v2.0 Usable on Linux

**Milestone:** v2.0
**Goal:** A Linux user can install Vortex, detect their Steam/Proton games, and download mods via NXM link.
**Status:** Active
**Last updated:** 2026-03-31

---

## Milestone Requirements

### Steam/Proton Detection (STAM)

- [ ] **STAM-01**: Steam game library VDF parsing works on Linux (native Steam install paths)
- [ ] **STAM-02**: All valid Steam library roots scanned and merged; Flatpak Steam paths (`~/.var/app/com.valvesoftware.Steam`) resolved; dual-install (Flatpak + native) handled correctly
- [ ] **STAM-03**: Proton prefix path resolved per-game from `steamapps/compatdata/`; never-launched games detected via `oslist` ACF field
- [ ] **STAM-04**: `{mygames}` variable resolves to correct Wine prefix location (`compatdata/<appid>/pfx/drive_c/users/steamuser/Documents/My Games`) on Linux; Windows resolution unchanged
- [ ] **STAM-05**: Top-4-title game extensions confirmed working on Linux: Skyrim SE, Fallout 4, Cyberpunk 2077, Stardew Valley (inherits STAM-04 fix for Bethesda titles)

### Packaging / Distribution (DIST)

- [ ] **DIST-01**: AppImage artifact (`vortex-setup-{version}.AppImage`) produced by electron-builder on Linux CI
- [ ] **DIST-02**: Debian package (`vortex_{version}_amd64.deb`) produced by electron-builder on Linux CI; `xdg-utils` and `libasound2` listed as deb dependencies
- [ ] **DIST-03**: GitHub Actions parallel Linux packaging job uploads AppImage, deb, and `latest-linux.yml` to GitHub releases alongside Windows artifacts
- [ ] **DIST-04**: `latest-linux.yml` auto-generated by electron-builder; in-app auto-updater gated behind `process.env.APPIMAGE` check; explicit `linux.artifactName` set in config to prevent filename drift

### NXM Protocol Handler (PROT)

- [ ] **PROT-01**: NXM "Download with Manager" works on standard Linux (GNOME, KDE Plasma) in both dev and AppImage builds — `ensureAppImageDesktopEntry()` writes `.desktop` file for AppImage builds; cold-start NXM URL buffered in `pendingDownload` field and applied after Redux store ready
- [ ] **PROT-02**: NXM handler validated on SteamOS/KDE Plasma Desktop Mode; `kbuildsycoca6 --noincremental` triggered after desktop DB update on KDE; Steam Browser NXM behavior documented (defer to v3.0 if hardware unavailable)

## Future Requirements (Deferred)

- **ELEV-01**: `pkexec` + Unix domain socket elevation for operations requiring elevated privileges on Linux — deferred to v3.0; v1.0 audit confirms not needed for Steam library operations
- **ELEV-02**: Elevation on Steam Deck (SteamOS) without polkit password — deferred to v3.0
- **DIST-05**: AppImage delta auto-update on SteamOS immutable filesystem — deferred to v3.0; `electron-updater` 4.2.0 behavior on SteamOS needs hardware validation
- **PROT-03**: NXM handler via Steam Browser overlay on Steam Deck — deferred to v3.0; WebKit-based Discover overlay `xdg-open` behavior unknown; requires Nexus Mods web team coordination

---

## Out of Scope

- pkexec / polkit implementation — v1.0 audit confirms not needed for Steam library operations; most libs are user-owned
- Native Linux game support (GOG, itch.io) — separate track, deferred to v4.0+
- Heroic Launcher integration — deferred to v4.0+
- Steam Deck Flatpak distribution — AppImage works in Desktop Mode; Flatpak sandbox restrictions on `~/.steam` need validation before investing
- Wine wrapper for FOMOD — rejected; native Linux binaries exist in npm packages
- Large codebase refactors — Windows code paths must remain untouched; all Linux support is additive
- gamebryo-savegame Linux compilation — MSVC exception constructors; deferred to v3.0
