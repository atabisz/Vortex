# Phase 16 — UI Design Contract

> Visual and interaction contract for Phase 16: chattr+F Filesystem Layer.
> Generated by gsd-ui-researcher.

## Phase UI Surface Assessment

This is a backend/filesystem phase. The **only** user-visible UI element is a single
informational notification (toast) shown at most once per session when the filesystem
is confirmed ext4 but the casefold feature (`-O casefold`) was not enabled at mkfs time.

All other conditions are silent. There are no new screens, dialogs, forms, buttons, lists,
or CTAs introduced in this phase. The notification dispatches through the injectable
`_setNotifier` seam in `fs.ts` and renders via Vortex's existing `INotification` system.
No new UI components are created.

## Copywriting Contract

This is the single UI deliverable for Phase 16. All copy is pre-populated from
CONTEXT.md decisions D-12, D-13, and the Specific Ideas section.

### Notification: ext4 without casefold (shown once per session)

| Field | Value |
|-------|-------|
| `type` | `"info"` |
| `title` | `"Kernel casefold unavailable"` |
| `message` | `"Your mod staging directory is on an ext4 filesystem without the casefold feature. Case-insensitive mod filenames will use the compatibility fallback. To enable kernel-level casefold, reformat with mkfs.ext4 -O casefold."` |

**Trigger condition:** `statfs` magic = `0xEF53` (confirmed ext4) AND `chattr +F` returns
`EOPNOTSUPP`. Fired at most once per session via module-level
`hasShownCasefoldNotification` flag in `fs.ts`.

**Non-triggers (no notification shown):**
- btrfs, XFS, ZFS, or any non-ext4 filesystem — silent fallback, no notification
- chattr+F succeeds — INFO log only, no notification
- Any other non-zero exit (EINVAL, ENOENT) — DEBUG log only, no notification
- Windows platform — platform-guarded, code never reached
- Flatpak sandbox — Flatpak-guarded, code never reached

### Empty State

Not applicable. Phase 16 introduces no list or data views.

### Error State

Not applicable. All failure modes fall back silently per CASE-07 (no error shown to user).
The EOPNOTSUPP notification is informational, not an error state.

### Primary CTA

Not applicable. The notification is read-only and informational. No button action.
The remediation (`mkfs.ext4 -O casefold`) is an offline user action documented in
the notification text.

### Destructive Actions

None. Phase 16 performs no destructive operations visible to the user.
