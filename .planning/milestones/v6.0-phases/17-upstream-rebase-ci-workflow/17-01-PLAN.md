Create `.github/scripts/rebase-upstream.sh` with executable permissions (`chmod +x`). The script consumes two environment variables injected by the workflow YAML: `GH_TOKEN` (GitHub token) and `UPSTREAM_REF` (optional tag override, empty string = auto-detect).

**Script structure (8 sequential steps):**

**Header:**
```bash
#!/usr/bin/env bash
set -euo pipefail
```

**Step 1 -- Add upstream remote and fetch tags (per D-01):**
```bash
UPSTREAM_REPO="https://github.com/Nexus-Mods/Vortex.git"
git remote add upstream "${UPSTREAM_REPO}" 2>/dev/null || git remote set-url upstream "${UPSTREAM_REPO}"
git fetch upstream --tags --no-recurse-submodules
```
The `2>/dev/null || set-url` handles the case where the remote already exists from a previous run.

**Step 2 -- Resolve target tag (per D-01, D-02, REBASE-05):**
- If `UPSTREAM_REF` is non-empty, use it directly as `UPSTREAM_TAG`.
- Otherwise, list all tags matching `v*`, grep for strict semver `^v[0-9]+\.[0-9]+\.[0-9]+$` (no pre-releases), sort with `sort -V`, take the last one with `tail -1`.
- If no tag found, echo "No upstream release tags found, exiting." and `exit 0`.

```bash
if [[ -n "${UPSTREAM_REF:-}" ]]; then
  UPSTREAM_TAG="${UPSTREAM_REF}"
else
  UPSTREAM_TAG=$(git tag --list 'v*' \
    | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' \
    | sort -V \
    | tail -1)
fi

if [[ -z "${UPSTREAM_TAG}" ]]; then
  echo "No upstream release tags found, exiting."
  exit 0
fi

echo "Target upstream tag: ${UPSTREAM_TAG}"
```

**Step 3 -- Check if already up to date (per REBASE-01, D-01):**
```bash
if git merge-base --is-ancestor "${UPSTREAM_TAG}" master; then
  echo "Fork master already includes ${UPSTREAM_TAG}, nothing to do."
  exit 0
fi
```

**Step 4 -- Create rebase branch (per REBASE-02):**
```bash
BRANCH="rebase/upstream-${UPSTREAM_TAG}"
git checkout -b "${BRANCH}" master
```

**Step 5 -- Attempt rebase with HAS_CONFLICTS flag (per REBASE-04, D-10):**
This is the critical section. The `if !` construct catches `git rebase` exit code 1 without `set -e` killing the script. On conflict: capture the conflicted file list BEFORE `git add -A` (per RESEARCH.md Open Question 1), then add all files including conflict markers and commit.

```bash
HAS_CONFLICTS=false
CONFLICT_FILES=""
if ! git rebase "${UPSTREAM_TAG}"; then
  echo "Rebase conflicts detected."
  HAS_CONFLICTS=true
  CONFLICT_FILES=$(git diff --name-only --diff-filter=U 2>/dev/null || echo "(see commit)")
  git add -A
  git commit --no-edit -m "rebase onto ${UPSTREAM_TAG} (conflicts)" || true
fi
```

**Step 6 -- Force-push branch (per REBASE-03):**
```bash
git push --force origin "${BRANCH}"
```

**Step 7 -- Build PR body (per REBASE-06, D-08, D-09):**
Compute fork base, commit count, and commit log. Build two distinct body strings depending on `HAS_CONFLICTS`.

```bash
FORK_BASE=$(git merge-base master "upstream/${UPSTREAM_TAG}" 2>/dev/null || echo "unknown")
COMMIT_COUNT=$(git rev-list --count "${FORK_BASE}..upstream/${UPSTREAM_TAG}" 2>/dev/null || echo "?")
COMMIT_LOG=$(git log --oneline "${FORK_BASE}..upstream/${UPSTREAM_TAG}" 2>/dev/null | head -20 || echo "(unavailable)")
```

Clean body (when `HAS_CONFLICTS` is false):
```
## Rebase onto upstream <TAG>

**Upstream tag:** `<TAG>`
**Upstream release:** https://github.com/Nexus-Mods/Vortex/releases/tag/<TAG>
**Conflict status:** Clean rebase
**Commits from fork base to upstream tag:** <COUNT>

### Upstream commits
\`\`\`
<COMMIT_LOG>
\`\`\`

---
Fork: https://github.com/atabisz/Vortex
```

Conflict body (when `HAS_CONFLICTS` is true):
```
## Rebase onto upstream <TAG>

**Upstream tag:** `<TAG>`
**Upstream release:** https://github.com/Nexus-Mods/Vortex/releases/tag/<TAG>

> [!WARNING]
> Conflicts detected -- manual resolution required before merging.

**Conflicted files:**
\`\`\`
<CONFLICT_FILES>
\`\`\`

---
Fork: https://github.com/atabisz/Vortex
```

Use a heredoc or variable assignment to build the multi-line `PR_BODY` string. Quote carefully to preserve newlines and backticks.

**Step 8 -- Idempotent PR creation (per REBASE-03, D-03, D-11):**
```bash
if ! gh pr list --head "${BRANCH}" --base master --json number --jq '.[0].number' | grep -q .; then
  gh pr create \
    --base master \
    --head "${BRANCH}" \
    --title "chore: rebase onto upstream ${UPSTREAM_TAG}" \
    --draft \
    --body "${PR_BODY}"
  echo "Draft PR created for ${BRANCH}."
else
  echo "PR already exists for ${BRANCH}, skipping creation."
fi
```

Always `--draft` (per D-11). Base is always `master`.

After creating the file, make it executable: `chmod +x .github/scripts/rebase-upstream.sh`.

**Part A: Create `.github/workflows/rebase-upstream.yml` (per D-04, D-05)**

This is a thin YAML file following the cherry-pick.yml structure exactly. The only differences from cherry-pick.yml are: the trigger (schedule + workflow_dispatch instead of pull_request_target), the job name (rebase instead of cherry-pick), the fork guard (atabisz/Vortex instead of merged check), and the env vars (GH_TOKEN + UPSTREAM_REF instead of PR metadata).

```yaml
name: Rebase Upstream

on:
  schedule:
    - cron: '0 6 * * *'
  workflow_dispatch:
    inputs:
      upstream_ref:
        description: 'Optional upstream ref to target (default: latest release tag)'
        required: false
        default: ''

permissions:
  contents: write
  pull-requests: write

jobs:
  rebase:
    if: github.repository == 'atabisz/Vortex'
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0

      - name: Configure Git
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

      - name: Rebase onto upstream
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          UPSTREAM_REF: ${{ inputs.upstream_ref }}
        run: bash .github/scripts/rebase-upstream.sh
```

Key details:
- `cron: '0 6 * * *'` runs daily at 06:00 UTC (Claude's discretion per CONTEXT.md).
- `inputs.upstream_ref` is `required: false` with `default: ''` (per REBASE-05).
- `if: github.repository == 'atabisz/Vortex'` is on the `rebase` job (per D-12, REBASE-07).
- `fetch-depth: 0` is mandatory for `git merge-base --is-ancestor` (per RESEARCH.md Pitfall 1).
- `permissions: contents: write` + `pull-requests: write` (per cherry-pick.yml pattern).
- Bot git identity matches cherry-pick.yml exactly: `github-actions[bot]` / `41898282+github-actions[bot]@users.noreply.github.com`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow_dispatch input -> shell script | `upstream_ref` user input flows into git commands |
| GitHub Actions runner -> nexus-mods/Vortex | Read-only fetch of upstream tags |
| GitHub Actions runner -> atabisz/Vortex | Write access via GITHUB_TOKEN (push branch, create PR) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Spoofing | rebase-upstream.yml | mitigate | `if: github.repository == 'atabisz/Vortex'` job-level guard prevents execution in forks-of-forks (REBASE-07/D-12) |
| T-17-02 | Tampering | rebase-upstream.sh (upstream_ref input) | mitigate | All shell variables double-quoted; `set -euo pipefail` catches unset vars; `upstream_ref` only used as git ref argument (not interpolated into URLs or commands unsafely) |
| T-17-03 | Tampering | rebase-upstream.sh (force push) | mitigate | Script pushes only to `rebase/upstream-*` branch namespace; `master` is never the push target; branch name derived from tag name which is filtered through semver regex |
| T-17-04 | Information Disclosure | PR body content | accept | PR body contains only git metadata (tag names, commit messages, file paths) -- no secrets, tokens, or private data are echoed |
| T-17-05 | Denial of Service | Daily cron + force push | accept | Each cron run triggers CI on rebase branch push (D-06/D-07); main.yml `concurrency: cancel-in-progress: true` limits resource usage; accepted trade-off per RESEARCH.md Pitfall 6 |
| T-17-06 | Elevation of Privilege | GITHUB_TOKEN scope | mitigate | Explicit `permissions: contents: write, pull-requests: write` block limits token scope to minimum required; no `repo` or `admin` scope |
</threat_model>
