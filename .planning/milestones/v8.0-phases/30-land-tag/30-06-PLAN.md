    Run the cherry-pick loop. For each SHA from `/tmp/cherry-pick-candidates.txt` in order:

    1. `git cherry-pick -x <sha>`.
    2. **On clean apply**: append a row to the `## Cherry-pick log` section: `<sha> | <subject> | applied`.
    3. **On conflict**:
        a. Inspect conflict files. Decide per D-30-03:
            - Default: linux-port HEAD wins → `git checkout --ours <file>; git add <file>`. (In cherry-pick, `--ours` = current HEAD = linux-port.)
            - If the cherry-picked content is genuinely Linux-relevant and missing on linux-port, hand-merge.
            - If the conflict is renderer-spine / main-spine churn that doesn't apply cleanly to linux-port's lighter scope: drop.
        b. If continuing: `git cherry-pick --continue`. Append a row: `<sha> | <subject> | resolved (--ours <file>)`.
        c. If dropping: `git cherry-pick --abort`. Append a row to `## Drops` section: `<sha> | <subject> | <reason>`.
    4. **On chain conflict** (3+ commits in a row all conflict): consider squashing the chain — `git cherry-pick --abort`, then `git cherry-pick -x --no-commit <sha1> <sha2> <sha3>` and amend a single combined commit. Document in 30-CHERRY-PICK-NOTES.md.

    **Borderline commits**: if a commit's subject suggests it could be Linux-only or could be cross-platform, EYEBALL the diff before cherry-picking:
    ```
    git show <sha> --stat
    ```
    If the diff is exclusively in `src/main/src/util/__platform__/linux/` or similar, include. If it's renderer-spine churn, drop with rationale.

    **Bluebird trap**: same as 30-01 rebase — if cherry-picking lands TS1064 due to bluebird Promise shadow, edit the file post-pick to remove the `:Promise<T>` annotation, amend the cherry-pick commit, document in notes.

    If a gate fails on linux-port (it shouldn't — gates are master-side invariants — but a Linux-specific guard might fail), document in notes.

    **Track progress**: count applied + dropped vs candidate total. Append a `## Running tally` line every ~30 picks: "Applied: N, Dropped: M, Remaining: K".
