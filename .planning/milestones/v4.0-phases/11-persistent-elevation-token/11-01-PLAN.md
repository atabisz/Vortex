Create `build/linux/10-vortex.rules` with the following exact content (per D-01, D-02, D-05):

```javascript
polkit.addRule(function(action, subject) {
  if (action.id === "io.nexusmods.vortex.run-elevated" && subject.active) {
    return polkit.Result.AUTH_ADMIN_KEEP;
  }
});
```

This is a polkit JavaScript rules file (not the older `.pkla` format). It:
- Matches the action ID `io.nexusmods.vortex.run-elevated` (same as in `io.nexusmods.vortex.policy`)
- Only applies when `subject.active` is true (user has an active desktop session)
- Returns `AUTH_ADMIN_KEEP` which caches the admin credential for the desktop session
- Does NOT add an `isInGroup("sudo")` guard (Claude's discretion: simpler, consistent with the `.policy` file's `<allow_active>auth_admin</allow_active>`)

The numeric prefix `10` ensures the rule runs early, before most system rules (per D-04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| polkit rules file -> system polkit daemon | Static rules file read by polkitd at auth decision time; determines credential caching behavior |
| .deb package -> filesystem | deb postinst installs files to system paths including /etc/polkit-1/rules.d/ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Elevation of Privilege | 10-vortex.rules | accept | Rule only grants AUTH_ADMIN_KEEP (credential caching), not AUTH_ADMIN or auth_self — user must still authenticate once per session. No privilege escalation beyond what the existing .policy file already authorizes. |
| T-11-02 | Tampering | /etc/polkit-1/rules.d/10-vortex.rules | accept | File installed to /etc/ owned by root; only root can modify. Standard deb package permission model. No additional mitigation needed beyond OS file permissions. |
| T-11-03 | Information Disclosure | 10-vortex.rules | accept | Rules file contains no secrets — only a polkit action ID and a result constant. No sensitive data exposed. |
| T-11-04 | Spoofing | io.nexusmods.vortex.run-elevated action ID | accept | Action ID is defined by the .policy file (already shipped in v3.0). Only processes calling pkexec with this action trigger the rule. Spoofing would require a malicious binary calling pkexec with the same action ID, which already requires user authentication. |
</threat_model>
