## Copywriting Contract

### ONBRD-06a — Linux Knowledge Base URL (no visible user-facing copy change)

The URL swap is invisible to the user in the happy path. No copy contract needed for
the URL itself.

### ONBRD-06b — Browser Launch Failure Notification

| Element | Copy |
|---------|------|
| Notification type | `"warning"` |
| Notification title | `"Could not open browser"` |
| Notification message | `"Visit: {{url}}"` (URL substituted at runtime) |
| Empty state heading | not applicable — notification only shown on failure |
| Empty state body | not applicable |
| Error state | The notification IS the error state — see message above |
| Destructive confirmation | none — no destructive actions in this phase |

**Rationale for "warning" over "error":**
The browser launch failure does not corrupt data or block further use of the app. The
user can still copy the URL from the notification. Using `"error"` level (red) would
misrepresent severity. `"warning"` (amber) signals "something didn't work as expected
but here is what you need."

**URL display:** The `{{url}}` value is the full URL string passed to `openUrl()`.
It should be plain text in the notification message, visible and selectable if the
Vortex notification rendering allows text selection. No href anchor is required — plain
visible URL is sufficient per D-04 (CONTEXT.md).

**Notification `id`:** `"open-url-failed"` — ensures deduplication if multiple URL
opens fail in quick succession. Each notification overwrites the previous via the same
`id` key, preventing notification spam.

**Notification `noDismiss`:** `false` — user should be able to dismiss once they have
copied the URL.

**Notification `allowSuppress`:** `false` — this is not a low-priority tip; it is a
failure message the user must be able to see.

## Interaction Contract

### open-knowledge-base event (ONBRD-06a)

| State | Behavior |
|-------|----------|
| Linux + `isModernLayout: true` | `generateUrl(wikiId) ?? LINUX_WIKI_URL` — uses `https://github.com/Nexus-Mods/Vortex/wiki/Vortex-on-Linux` as fallback instead of generic `WIKI_URL` |
| Linux + `isModernLayout: false` | No URL opened — shows in-app Knowledge Base page; Linux URL not needed for this branch |
| Non-Linux (any layout) | Existing behavior unchanged |

The only visible interaction change: Linux users who click Help > Knowledge Base (in
modern layout) land on the Linux-specific wiki page. This is a URL routing change — no
visible UI difference beyond the browser destination.

### opn() / shell.openExternal() failure (ONBRD-06b)

| State | Behavior |
|-------|----------|
| Browser opens successfully | No change — same as before |
| Browser launch fails (any platform) | `api.sendNotification({ type: "warning", id: "open-url-failed", title: "Could not open browser", message: "Visit: {{url}}", replace: { url } })` |

The notification appears in the existing Vortex notification panel (top-right by
convention). No modal, no dialog, no blocking interaction. User can dismiss it or copy
the URL manually.
