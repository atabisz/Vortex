## Scope Note

Phase 18 is predominantly a logic-and-guards phase. The only net-new UI surface is
a Linux-specific empty-state block inside `NoGameDashlet.tsx` (ONBRD-01d). All other
changes (crash guards in `todos.tsx`, `getDriveList.ts` fallback, manual-scan condition,
auto-retry) produce no visible DOM changes — they prevent crashes or silently correct
data. The design contract below covers only what changes visually.

## New UI Surface: Linux Empty State in NoGameDashlet

This is the only visual deliverable in Phase 18.

### Trigger condition

Rendered when ALL of the following are true:
- `process.platform === 'linux'`
- `games.length === 0` (no discovered games after filtering)
- `discoveryRunning === false`

### Layout

```
[ NoGameDashlet existing wrapper ]
  <div className="no-game-linux-empty-state">
    <h4 className="empty-state-heading">No Steam games detected</h4>
    <p className="empty-state-body">
      Make sure Steam has finished loading, then click Refresh.
    </p>
    <Button bsStyle="primary" onClick={onRefresh}>
      Refresh
    </Button>
  </div>
```

Wrapper class `no-game-linux-empty-state`: flex column, align-items center, gap 8px,
padding 16px, background `$brand-menu`, border-radius `$border-radius-base` (4px).

The block renders INSIDE the existing `NoGameDashlet` component render method, as an
additional branch after the `games` array is computed. It does NOT replace the existing
welcome heading and instruction text — it is an additional conditional block that appears
beneath them when the trigger condition is met.

### Button

- Component: `<Button>` from `react-bootstrap` with `bsStyle="primary"`
- Label: "Refresh" (see Copywriting Contract below)
- Action: emits `"start-discovery"` via `this.context.api.events.emit`
- Width: auto (inline, not full-width)
- Minimum height: 44px (accessibility touch target)
- Do NOT use `IconButton` here — a plain `Button` is appropriate for a primary action

## Copywriting Contract

All copy is English-only. String additions must use NEW conditional branches wrapping
`t("...")` literals — never edit existing `t("...")` calls in-place (breaks Windows
wording and stales locale caches per STATE.md Research Context).

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA (Refresh button) | "Refresh" | Verb only — matches existing "Scan for missing games" action brevity |
| Empty-state heading | "No Steam games detected" | Direct statement of state; no exclamation |
| Empty-state body | "Make sure Steam has finished loading, then click Refresh." | Actionable; names the button so the user knows what to click |
| Manual-scan todo (existing, now always visible on Linux) | "Scan for missing games" | Existing string — do NOT change |
| Manual-scan todo running state (existing) | "Discovery running" | Existing string — do NOT change |
| getDriveList fallback (no UI copy) | n/a | Silent fallback, debug-log only; no user-facing string |
| minDiskSpace guard (no UI copy) | n/a | Hides the disk-space todos; no new string shown |

No destructive actions in Phase 18. No destructive confirmation copy needed.

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Refresh button click | Emits `"start-discovery"`. Button becomes unreachable while `discoveryRunning === true` (empty-state block only shows when `discoveryRunning === false`, so the button is naturally hidden during active discovery). |
| Auto-retry (ONBRD-01e) | Silent — no spinner, no toast, no status change visible to user. Happens in `GameStoreHelper.ts` data layer. If retry also returns empty, `NoGameDashlet` empty-state renders as normal. |
| getDriveList fallback | Silent — no UI change. Returns `['/']` instead of `['C:']`. User sees Linux mount points in game-search drive list. |
| manual-scan always visible | No new interaction. Existing todo row is always shown on Linux regardless of `searchPaths`. The dismiss button behavior is unchanged. |
