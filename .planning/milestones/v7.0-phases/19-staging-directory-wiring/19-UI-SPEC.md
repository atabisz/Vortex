## Copywriting Contract

Phase 19 changes are primarily platform-guarded string replacements. The Windows text is never deleted — a Linux branch is added alongside it.

### Disk-Space Todos Visibility (ONBRD-02a)

No new copy required. The `mod-location` and `download-location` todo cards use their existing labels. The value renderer already shows the raw path string (wired in Phase 18). The only change is the `minDiskSpace()` condition returns `true` on Linux.

| Element | Copy |
|---------|------|
| `mod-location` todo label | (existing, unchanged) |
| `download-location` todo label | (existing, unchanged) |
| Todo value (Linux) | Raw path string — already rendered by Phase 18 value branch |

### Partition-Exists Dialog (ONBRD-02b)

No new copy. The existing `Reinitialize` path triggers the existing "can't purge" Bootstrap modal dialog. The fix is behavioral (correct dialog fires on missing dir) — the dialog copy itself is unchanged.

### Windows Path Examples — Linux Replacements (ONBRD-02c)

These are the primary copywriting deliverables. All three locations get a Linux arm under `process.platform === 'linux'`. Windows text is preserved unchanged.

| Location | Windows text (unchanged, Windows only) | Linux replacement text |
|----------|----------------------------------------|------------------------|
| `texts.ts` `downloadspath` case — example path | `C:\Users\Mike\AppData\Roaming\Vortex\Downloads\` | `~/.local/share/Vortex/downloads` |
| `texts.ts` `modspath` case — example path | `d:\vortex_mods\{GAME}` and `d:\vortex_mods\skyrim` | `~/.local/share/Vortex/mods/{GAME}` and `~/.local/share/Vortex/mods/skyrim` |
| `Settings.tsx` staging toggle tooltip — default path example | `c:\Users\<username>\AppData\Roaming\Vortex\<game>` | `~/.local/share/Vortex/<game>` |
| `Settings.tsx` staging toggle tooltip — suggested path example | `<drive>:\{suggestionPattern}\<game id>` | `/{mountpoint}/vortex_mods/<game id>` |

String format rules:
- Use `~/.local/share/Vortex/` as the Linux user data prefix — matches D-08 in CONTEXT.md
- Use lowercase `<game>` placeholder in tooltip copy — consistent with existing style
- Use `/{mountpoint}/vortex_mods/<game id>` for the suggested-path arm — matches D-08
- Do not use `$HOME` in user-visible text; use `~` which is more readable per CONTEXT.md D-08 (Claude's Discretion)
- All strings passed through `t()` — i18n required even for platform-guarded arms

### Suggested Staging Path (ONBRD-02d)

No visible copy change. The `suggestStagingPath()` return value is used as the default staging directory string. It appears in settings UI wherever the staging path is displayed. No dialog copy changes; the path value itself changes to be device-aware.

### Primary CTA

| Element | Copy |
|---------|------|
| Primary CTA (staging directory setup) | "Change" (existing Settings button label — unchanged) |
| Empty state heading | Not applicable — todos are now always visible on Linux |
| Empty state body | Not applicable |
| Error state (missing staging dir) | (existing dialog copy, unchanged) — "The staging folder for {game} could not be found. Reinitialize?" |
| Destructive confirmation | Not applicable — no destructive actions introduced in this phase |

Note: "Change" is an existing UI label inherited from the Settings panel. It is a single-word label that is not subject to renaming in this phase — the phase adds no new buttons and does not modify existing CTA labels.

Source: CONTEXT.md decisions D-01 through D-09, REQUIREMENTS.md ONBRD-02a through ONBRD-02d
