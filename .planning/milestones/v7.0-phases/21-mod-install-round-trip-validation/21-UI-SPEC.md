## Phase Character

Phase 21 is a **code-fix phase** (CONTEXT.md D-01). No new UI components are introduced.
The phase fixes deploy-method selection (hardlink_activator availability for Skyrim SE on Linux)
and adds a UAT checklist to Phase 999.1 backlog. All UI surface touched by this phase exists
already: the Mods page toolbar, the deployment settings panel, and error/notification toasts.

This spec governs the interaction contracts for those **existing surfaces** — specifically the
error paths and notification copy that must be correct for a successful round-trip on Linux.

## Copywriting Contract

Phase 21 fixes deploy-method selection. The following copy applies to the interaction
surfaces that the fix touches. All copy must use `t()` wrapping for i18n consistency
with the existing pattern (CONTEXT.md accumulated decisions — ternary inside t() for
platform-specific arms).

| Element | Copy |
|---------|------|
| Primary CTA (deploy) | "Deploy Mods" — existing string in `ActivationButton.tsx`; do not change |
| Deploy method missing warning | "You have to select a deployment method first" — existing; do not change |
| Deploy method settings link | "Fix" (action button) — existing; do not change |
| Deployment success notification | "Mods deployed" — existing `sendNotification` in `ActivationButton.tsx`; do not change |
| Deploy method unavailable (Linux) | If hardlink_activator.isSupported returns a reason on Linux, the error must include the reason string from `IUnavailableReason.description` — do not add new ad-hoc strings; surface the structured reason |
| Empty deploy method list | "You need to select a deployment method in settings" — existing in `ActivationButton.tsx`; do not change |
| UAT checklist entry (999.1 backlog) | "ONBRD-04: Install, deploy, and enable a mod for Skyrim SE on Linux — code-complete; hardware UAT pending" |

**Destructive actions in this phase:** None. Phase 21 does not introduce any destructive
operations. No confirmation dialogs are added.

**Error state pattern:** All errors surface via the existing `showError(dispatch, message, details)`
utility. The `details` param accepts an error object or string. For deploy-method failures on Linux,
pass `IUnavailableReason.description` as the `details` string so the user sees a specific reason,
not a generic message. Do not introduce new error UI.

**Empty state:** Not applicable. Phase 21 does not create a new page or list. If the deploy method
list is empty, the existing `EmptyPlaceholder` component with the existing copy applies.

## Interaction States

The deploy-method selection flow has four observable states. Each must behave correctly
for Skyrim SE on Linux after the Phase 21 fix:

| State | Trigger | Expected Behaviour |
|-------|---------|-------------------|
| No activator selected | Fresh Linux install | Settings modal opens; hardlink_activator appears in list as available option |
| hardlink selected (default) | `getSupportedActivators` returns hardlink at priority 5 | "Deploy Mods" button is active (no flash); clicking emits `deploy-mods` event |
| Deploy in progress | `deploy-mods` event emitted | Existing spinner/progress indicator; no change needed |
| Deploy complete | Callback fires with null | "Mods deployed" notification (info, 3000ms) — existing behaviour |
| Deploy failed | Callback fires with Error | `showError` dialog with error details — existing behaviour |
