**Step 1: Create `src/stylesheets/vortex/dialog-steam-deck.scss`** with exactly this content:

```scss
// Steam Deck Desktop Mode (1280x800) -- prevent modal action buttons
// from being pushed below the visible area at 800px viewport height.
// max-height is a no-op at typical Windows viewport heights (1024px+).
.modal-dialog {
    max-height: calc(100vh - 160px);
    overflow-y: auto;
}

.modal-content {
    display: flex;
    flex-direction: column;
    height: 100%;
}

.modal-body {
    overflow-y: auto;
}

.modal-footer {
    flex-shrink: 0;
}
```

Per D-04: Global rules using class selectors only (no ID scope) -- applies to ALL Bootstrap modals.
Per D-05: New file at `src/stylesheets/vortex/dialog-steam-deck.scss`.
Per D-06: Three required rules: `.modal-dialog { max-height; overflow-y }`, `.modal-content { flex-direction: column; height: 100% }`, `.modal-footer { flex-shrink: 0 }`.
Per D-07: No platform guard -- unconditional CSS.

Discretion exercised: `.modal-body { overflow-y: auto; }` is added per RESEARCH.md Open Question 1 recommendation. This ensures body content scrolls within the flex container for non-FOMD dialogs that lack `flex: 1 0%`. For dialogs that already have `flex: 1 0%` (like FOMD), `overflow-y: auto` is harmless. For ID-scoped dialog rules (e.g., `#fomod-installer-dialog`), the higher-specificity existing rules take precedence.

Specificity note: These class-only selectors have the same specificity as rules in `dialogs.scss`. The import order (after `dialog-history`) ensures `dialog-steam-deck.scss` wins the cascade for same-specificity conflicts. ID-scoped rules in `dialog-fomod.scss` are NOT overridden (higher specificity).
