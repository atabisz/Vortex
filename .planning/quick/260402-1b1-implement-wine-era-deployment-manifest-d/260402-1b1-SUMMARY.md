# Quick Task 260402-1b1: Wine-era Deployment Manifest Detection Summary

**One-liner:** Wine/Proton manifest detection with targeted Linux purge dialog and backslash normalization in activationStore.

## What Was Done

Added Wine-era deployment manifest detection to `loadActivation()` in `activationStore.ts`. Users migrating from Wine/Proton-based Vortex to native Linux Vortex now get a clear, specific dialog instead of the confusing "different instance" dialog.

### New Functions

**`isWineEraManifest(manifest: IDeploymentManifest): boolean`**
- Returns `false` unconditionally when `process.platform !== "linux"` — Windows is never affected
- On Linux, checks `manifest.stagingPath` and `manifest.targetPath` against `/^[A-Za-z]:\\/`
- Returns `true` if either path starts with a Windows drive letter (e.g. `Z:\`, `C:\`)

**`queryPurgeWineEra(api, basePath, files): Promise<void>`**
- Shows dialog titled "Wine/Proton deployment detected" with 4-sentence explanation
- On Purge: normalizes backslashes in `relPath` entries (`\\` → `/`) before calling `purgeDeployedFiles`
- On Cancel or purge error: rejects with `UserCanceled`
- Follows existing `queryPurge` Bluebird `.then()/.catch()` chain style

### Modified Function

**`loadActivation()`**
- Added `if (isWineEraManifest(tagObject) && tagObject.files.length > 0)` block BEFORE the existing instance-mismatch check
- On Wine-era detection: calls `queryPurgeWineEra` → `saveActivation(..., [], activator.id)` → resolves with `[]`
- Existing `else if (tagObject.instance !== instanceId ...)` block completely unchanged
